Notes — complexity & design rationale

Algorithm analysis (DAA)

Each level of the state space tree fixes one element (include or exclude), so for n elements the tree has at most 2n+1 − 1 nodes and the worst-case running time is O(2n), plus O(n) to output each solution. Pruning when s > M and stopping when s = M only cut off subtrees. That helps in practice but does not change the worst case. Extra space is O(n): the recursion is at most n + 1 calls deep and the decision vector x holds n entries. For the current input the search generates of the nodes in the full tree.

Textbook variants often sort w and add a second bound (s + remaining < M). This tool deliberately uses only the s > M bound so every node matches the rule stated in the assignment.

UI/UX decisions

The tree gets the largest panel because it is what students are studying. The pseudocode and running-state panels sit next to it, so every step can be matched to a line of code and to concrete numbers (the partial sum and remaining budget). Node status is shown three ways at once (colour, an icon badge and a text caption), and include/exclude edges differ by label (✓/✗) and line style (solid/dashed). This keeps the diagram readable in greyscale and for colour-blind users. Animations stay under 300 ms, and the one accent colour (indigo) is used only to mark “where you are now”. Tutorial and Execution modes share the same explanation card, so the wording is identical whether you step through the tree or click around it.
